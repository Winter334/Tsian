# 世界配置独立化与编辑工作台实施方案

## 1. 文档目的

本文档只讨论**当前阶段需要落地的内容**，目标是把当前仍绑定在预设体系中的世界配置拆分出来，并为后续扩展到更完整的叙事生态打下稳定基础。

本文档**不尝试提前设计完整的长期目标架构**。长期目标只在另一份文档中作为设计原则和方向描述，不作为当前阶段的实现约束。

相关现状依据：

- 运行时世界规则真源已经是 [`getRuntimeWorldConfig()`](../src/lib/world/resolve-config.ts:26) 与存档快照中的 `worldConfig`
- 作者态模板仍挂在 [`Preset.worldConfig`](../src/lib/prompt/types.ts:122)
- 当前世界配置的机械规则主体是 [`WorldConfig`](../src/lib/world/types.ts:228)
- 现有世界书链路入口是 [`collectWorldInfoContentSync()`](../src/lib/lorebook/collector.ts:68)
- 现有世界档案仓储入口是 [`getWorldArchiveRepository()`](../src/modules/world-archive/repository.ts:230)
- 当前剧情上下文槽位是 [`scenario`](../src/lib/prompt/types.ts:219)，渲染入口是 [`renderScenario()`](../src/lib/prompt/marker-registry.ts:1208)
- 当前聊天初始化只有默认会话，没有专门的开幕语注入链路，相关入口见 [`ensureDefaultConversation()`](../src/modules/chat/index.ts:27) 与 [`sendMessageHandler()`](../src/modules/chat/commands/handlers.ts:69)

---

## 2. 当前阶段的核心目标

当前阶段只聚焦 4 件事：

1. **将世界配置从预设中独立出来**
2. **为独立世界配置提供可视化编辑 UI**
3. **在独立世界配置中纳入剧本与开幕语**
4. **为后续 世界配置—导演AI—世界档案 生态留出正确扩展接口**

换句话说，当前阶段的目标不是一次性做完完整生态，而是先完成“**世界对象独立化 + 编辑工作台 + 初始叙事启动能力**”这条最短闭环。

---

## 3. 当前阶段的对象边界

### 3.1 当前阶段应引入的核心对象

当前阶段建议引入一个独立的**世界配置对象**，其内部采用两层结构：

1. **规则层**
   - 对齐 [`WorldConfig`](../src/lib/world/types.ts:228)
   - 承载属性、衍生属性、检定、状态、天赋、角色创建维度、物品模板、技能模板、背包规则等

2. **叙事启动层**
   - 承载 `script`
   - 承载 `opening`
   - 承载与首次开局、导演 AI 冷启动有关的初始叙事材料

### 3.2 当前阶段不应并入的对象

以下内容当前阶段**不要强行并入世界配置主体**：

1. **世界书**
   - 继续保持独立系统
   - 世界配置只负责绑定、关联或引用
   - 不把世界书条目揉进大一统 schema

2. **世界档案**
   - 继续保持独立系统
   - 当前阶段只考虑未来如何与其衔接，不在这一轮重构中重做档案模型

3. **导演 AI 管理逻辑**
   - 当前阶段只为它预留接入位
   - 不在这一轮里完成完整导演调度系统

### 3.3 当前阶段的语义约束

- **规则层**回答的是：这个世界如何运作
- **剧本**回答的是：这一轮冒险朝什么方向展开
- **开幕语**回答的是：玩家第一次进入聊天时看到什么
- **世界书**回答的是：世界中有哪些静态知识
- **世界档案**回答的是：运行中有哪些叙事实体及其当前状态

## 4. 当前阶段对剧本与开幕语的定义

### 4.1 剧本 `script`

当前阶段中，`script` 的定位如下：

- 是世界配置中的**叙事启动材料**
- 是导演 AI 后续进行剧情组织与安排的基础输入
- 内容可以非常自由，从简单创作方向到完整剧情大纲都允许
- 当前阶段不要求把剧本拆成章回、节点、事件图等复杂结构
- 当前阶段应优先以**自由文本**形态落地

当前阶段的接入建议：

- 将其作为 [`scenario`](../src/lib/prompt/types.ts:219) 的正式上游来源
- 通过 [`renderScenario()`](../src/lib/prompt/marker-registry.ts:1208) 接入现有提示词装配链路
- 先解决“有稳定来源”问题，再考虑后续结构化增强

### 4.2 开幕语 `opening`

当前阶段中，`opening` 的定位如下：

- 是**玩家可见**的首屏文本
- 出现在玩家第一次输入之前
- 作用是锚定剧情开端，并辅助导演 AI 与叙事链路完成冷启动
- 它不是系统提示词，不是隐藏指令，也不应仅作为内部 prompt 片段存在

当前阶段的接入建议：

- 将其接到会话初始化链路
- 不挂入普通玩家输入链路 [`sendMessageHandler()`](../src/modules/chat/commands/handlers.ts:69)
- 重点围绕 [`ensureDefaultConversation()`](../src/modules/chat/index.ts:27) 附近的初始化流程建立“一次性注入”能力
- 要避免在重复加载存档时多次注入同一开幕语

## 5. 当前阶段 UI 方案

## 5.1 总体结论

当前阶段建议采用**混合式世界编辑工作台**，而不是纯表单，也不是纯文档块系统。

用户已经明确表达：

- 接受混合式编辑
- 需要提供基础表单
- 也需要允许直接编辑配置文件
- 不需要以预览为核心的设计

因此，当前阶段 UI 的定位应为：

**结构化编辑优先，原始配置直编兜底，不把预览当成主能力。**

### 5.2 推荐布局

建议采用全屏工作区，风格参考：

- [`PresetWorkspace`](../src/components/PresetWorkspace/PresetWorkspace.tsx)
- [`LorebookWorkspace`](../src/components/LorebookWorkspace/LorebookWorkspace.tsx)

建议布局：

1. **左侧导航区**
   - 世界列表
   - 分类导航
   - 导入导出入口

2. **中间编辑区**
   - 当前分区的主要编辑界面
   - 结构化表单与原始配置切换

3. **右侧辅助区**
   - 不是预览区
   - 主要用于显示字段说明、schema 校验结果、依赖提示、风险警告

### 5.3 推荐分区

1. **基础信息**
   - 名称
   - 描述
   - 标签
   - 版本
   - 来源说明

2. **规则配置**
   - 对齐 [`WorldConfig`](../src/lib/world/types.ts:228)
   - 结构化表单为主
   - 关键复杂区块允许切换为原始配置编辑

3. **叙事启动**
   - `script`
   - `opening`
   - 文本编辑为主

4. **外部绑定**
   - 世界书绑定
   - 世界档案相关绑定占位
   - 未来扩展说明

5. **导入导出**
   - 导入独立世界配置
   - 导出独立世界配置
   - schema 校验说明

### 5.4 表单与配置文件直编的关系

当前阶段建议采用“双轨编辑”：

1. **基础用户路径**
   - 使用结构化表单
   - 降低学习成本
   - 提供更明确的字段说明与约束

2. **高级用户路径**
   - 提供原始配置编辑能力
   - 适合自由扩展与快速修改
   - 用于承接世界配置的高自由度需求

但要注意：

- 原始配置编辑不是替代结构化模型
- 原始配置编辑应建立在明确 schema 边界之上
- 当前阶段不建议把整个系统退化成“纯 JSON 文本编辑器”

## 6. 当前阶段必须完成的实现范围

以下内容属于**当前阶段必须完成**的范围。

### 6.1 世界配置脱离预设

需要完成：

1. 新建独立世界配置对象的存储模型
2. 将作者态世界模板从 [`Preset.worldConfig`](../src/lib/prompt/types.ts:122) 迁出
3. 清理预设继续承担世界真源职责的路径
4. 明确世界配置作为作者态世界来源

### 6.2 新建独立世界编辑工作台

需要完成：

1. 独立入口
2. 世界列表管理
3. 基础信息编辑
4. 规则配置编辑
5. 剧本与开幕语编辑
6. 基础导入导出
7. 原始配置直编能力

### 6.3 建档与向导改造

需要完成：

1. 新建存档与建房流程改为从独立世界配置取源，而不是从活动预设取源
2. [`GameWizard`](../src/components/GameWizard/index.tsx:75) 需要以所选世界配置驱动角色创建流程
3. 联机模式继续保留 Host 权威选择模型

### 6.4 剧本与开幕语接入

需要完成：

1. `script` 有稳定存储来源
2. `script` 稳定接入 [`scenario`](../src/lib/prompt/types.ts:219) 链路
3. `opening` 有独立字段
4. `opening` 在会话初始化时只注入一次

## 7. 当前阶段暂不处理但要预留接口的内容

以下内容当前阶段**不作为必须落地目标**，但必须在设计上避免堵死后路。

### 7.1 导演 AI 对世界档案的持续管理

当前阶段暂不完成：

- 导演 AI 每回合增删改世界档案
- 导演 AI 主动筛选叙事实体并分发给解析 AI / 叙事 AI
- 导演 AI 基于剧情正文自动提取事件、地点、势力、任务等语义实体

但当前阶段应预留：

- 世界配置中的预设叙事实体未来可进入世界档案的语义通道
- 剧本作为导演 AI 的稳定上游输入
- 世界配置对象支持携带未来可转译为档案实体的初始叙事材料

### 7.2 世界档案模型重构

当前阶段暂不完成：

- 将预设叙事实体与运行时实体统一纳入同一档案系统
- 将无数据支撑的语义标签实体与有结构化数据的实体统一抽象
- 重构档案仓储与导演调度接口

但当前阶段应预留：

- 世界配置中的预设叙事实体未来可转换为世界档案中的基础图书
- 对有数据实体与无数据实体的差异保留扩展空间

### 7.3 智能注入与精细化分发

当前阶段暂不完成：

- 导演 AI 向解析 AI 提供实体 ID 驱动的精确恢复机制
- 导演 AI 向叙事 AI 注入动态整理后的剧情指导摘要
- 更细粒度的档案检索与动态上下文编排

但当前阶段应避免：

- 把所有叙事实体重新塞回全量 prompt 注入
- 把未来导演调度能力提前硬编码成单一路径

## 8. 当前阶段的设计原则

### 8.1 不再让预设承担世界真源职责

预设未来只保留：

- AI 行为风格配置
- 预览时的外部世界上下文绑定
- 与世界配置解耦后的提示词创作职责

而不再承担：

- 运行时世界规则真源
- 世界启动内容真源

### 8.2 不把世界书与世界档案揉成同一套编辑器

当前阶段应坚持：

- 世界编辑器负责规则与启动内容
- 世界书负责静态知识
- 世界档案负责叙事实体状态

三者可以协作，但不在这一轮里被强行做成一个巨型工作区。

### 8.3 先解决“稳定来源”，再追求“智能治理”

当前阶段应优先解决：

- 世界配置独立存储
- 剧本稳定接入
- 开幕语稳定接入
- 建档与联机流程稳定改造

而不是过早进入：

- 完整导演 AI 编排
- 档案自治
- 高阶叙事实体生命周期治理

### 8.4 UI 以可编辑性为主，而不是展示性为主

当前阶段不应把主要精力放在：

- 炫目的预览
- 不稳定的模拟渲染
- 中看不中用的复杂演示面板

当前阶段应优先：

- 可编辑
- 可校验
- 可导入导出
- 可维护
- 可为未来扩展留口

## 9. 当前阶段建议拆解的工作包

### 工作包 A：数据模型独立化

目标：

- 从预设中拆出独立世界配置对象
- 保持运行时快照模式不变

产出：

- 新世界配置对象 schema
- 预设与世界配置的职责重划分
- 创建流程新的世界取源定义

### 工作包 B：世界编辑工作台

目标：

- 提供独立 UI
- 允许表单编辑与配置直编

产出：

- 工作台信息架构
- 分区 UI
- 导入导出入口

### 工作包 C：建档与向导接源改造

目标：

- 让世界配置替代预设，成为创建流程的世界来源

产出：

- 建档入口选择世界
- 向导按世界规则驱动
- 联机 Host 权威选择

### 工作包 D：剧本与开幕语接入

目标：

- 建立完整的叙事启动闭环

产出：

- `script` → [`scenario`](../src/lib/prompt/types.ts:219)
- `opening` → 会话初始化链路

## 10. 当前阶段的验收口径

如果当前阶段完成，应至少满足以下结果：

1. 世界配置可以独立于预设存在与编辑
2. 新建流程不再依赖活动预设提供世界规则
3. 世界编辑 UI 能够完成基础规则配置编辑
4. 世界编辑 UI 能够完成 `script` 与 `opening` 编辑
5. `script` 能稳定进入现有提示词链路
6. `opening` 能稳定作为首次会话内容出现且不重复注入
7. 世界书与世界档案虽然未重构，但后续可接入路径不被堵死

---

## 11. 当前阶段明确不做的事

为避免范围失控，当前阶段明确不做：

1. 不重构完整世界档案系统
2. 不提前设计最终导演 AI 全流程
3. 不实现复杂的长期迁移路线系统
4. 不把所有叙事实体统一成最终形态模型
5. 不把 UI 做成以预览为核心的工作区
